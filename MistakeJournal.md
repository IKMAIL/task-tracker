# Mistake Journal

| #   | Mistake | Cause | Lesson Learned | Fixed Code Reference |
| --- | ------- | ----- | -------------- | -------------------- |
| 1   | Called `apiFetch<AuditResponse>(...)` with a generic type argument that doesn't exist on the function | Assumed `apiFetch` was a typed generic like axios — it returns `Promise<any>` with no type parameter | Always verify a function's type signature before using generic type arguments; don't assume type-parameterization without reading the definition | `apps/web-frontend/src/api/auditApi.ts` — removed `<AuditResponse>` from `apiFetch` call |
| 2   | Accessed `auditData?.data` and `auditData.meta.total` after fetching via `useFetch` | `useFetch` auto-unwraps `result?.data ?? result`, so the returned `data` is already the array — the `{ data, meta }` envelope is stripped | `useFetch` always unwraps `.data` from responses. Never access `.data` or `.meta` on a `useFetch` result; use the value directly and `.then(r => r.data)` in the fetch call when needed | `apps/web-frontend/src/pages/TaskDetailPage.tsx` — added `.then(r => r.data)`, replaced `auditData?.data` with `auditData`, replaced `auditData.meta.total` with `auditData.length` |
| 3   | mcp-server tsconfig `rootDir: "src"` causes TS6059 when `@task-tracker/utils` resolves to source .ts files under `node16` moduleResolution | workspace symlink + `node16` resolution follows source .ts files when package has no `types` field; no `types` field meant TypeScript fell through to raw source | Always add `"types": "dist/index.d.ts"` to monorepo workspace packages so TypeScript uses compiled declarations regardless of resolution mode | `shared/utils/package.json` — added `"types": "dist/index.d.ts"` |
| 4   | `registerTool(inputSchema: z.object({...}))` caused TS2589 deep type instantiation errors in MCP SDK | MCP SDK `registerTool` expects `ZodRawShapeCompat` (plain `Record<string, ZodType>`) not a wrapped `ZodObject`; wrapping triggers unbounded Zod type inference chain | Pass raw Zod shape `{ field: z.string() }` not `z.object({ field: z.string() })` to MCP SDK `registerTool inputSchema` | `services/mcp-server/src/tools/*.ts` — changed all `z.object({...})` to raw shape objects |
| 5   | `tool.callback(...)` in tests — `callback` is not a property on MCP SDK v1.27 registered tools | Assumed MCP SDK used `callback` for the tool handler; actual property is `handler` | Always inspect the SDK's internal structure (or source) before accessing private fields in tests; property names differ across versions | `tests/tools.test.ts` — changed `tool.callback(...)` to `tool.handler(...)` |
