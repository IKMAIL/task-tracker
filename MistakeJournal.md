# Mistake Journal

| #   | Mistake | Cause | Lesson Learned | Fixed Code Reference |
| --- | ------- | ----- | -------------- | -------------------- |
| 1   | Called `apiFetch<AuditResponse>(...)` with a generic type argument that doesn't exist on the function | Assumed `apiFetch` was a typed generic like axios — it returns `Promise<any>` with no type parameter | Always verify a function's type signature before using generic type arguments; don't assume type-parameterization without reading the definition | `apps/web-frontend/src/api/auditApi.ts` — removed `<AuditResponse>` from `apiFetch` call |
| 2   | Accessed `auditData?.data` and `auditData.meta.total` after fetching via `useFetch` | `useFetch` auto-unwraps `result?.data ?? result`, so the returned `data` is already the array — the `{ data, meta }` envelope is stripped | `useFetch` always unwraps `.data` from responses. Never access `.data` or `.meta` on a `useFetch` result; use the value directly and `.then(r => r.data)` in the fetch call when needed | `apps/web-frontend/src/pages/TaskDetailPage.tsx` — added `.then(r => r.data)`, replaced `auditData?.data` with `auditData`, replaced `auditData.meta.total` with `auditData.length` |
| 3   | No error handling in `ChecklistSection` UI mutations — failed API calls throw unhandled promise rejections with no user feedback | Async event handlers written as bare `await` without `try/catch`; assumed happy path only | Always wrap UI-triggered async calls in `try/catch` and reflect failure state to the user | `ChecklistSection.tsx` — gap fix E |
| 4   | `syncProgress` used `{ ...data, completionPct: undefined }` to exclude a field | Relied on Mongoose silently stripping `undefined` from `$set` — implicit behaviour, not a documented contract | Use explicit destructuring (`const { field: _omit, ...rest } = obj`) to exclude fields; never rely on `undefined` being silently ignored | `taskService.ts` — gap fix C |
| 5   | No unit tests written for `computeCompletionPct` or checklist endpoints | Tests were not included in the original implementation plan todo list | New service logic (especially pure functions with edge cases) must have tests in the same PR; add a "tests" item to every backend feature plan | `tests/checklist.test.ts` — gap fix D |
| 6   | `tasks/todo.md` items left unchecked and review section empty after implementation | Forgot to update the plan file after completing work | Mark todo items done immediately after finishing each one; write the review section before the final commit | `tasks/todo.md` — gap fix A |
| 7   | `MistakeJournal.md` not created despite being required by `LEARNING.md` | Skipped reading `.claude/LEARNING.md` before starting the task | Always read all three `.claude/` instruction files (WORKFLOW.md, INSTRUCTIONS.md, LEARNING.md) before starting any task | This file — gap fix B |
