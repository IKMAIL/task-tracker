# Architecture Decision Records

This directory contains all Architecture Decision Records (ADRs) for this project.

ADRs document significant technical decisions — what was decided, why, what alternatives were considered, and what the consequences are. They prevent the same debate from happening again mid-sprint and give new team members context on why things are the way they are.

## ADR Status Values

- **Proposed** — Decision is under discussion, not yet confirmed
- **Accepted** — Decision is confirmed and in effect
- **Deprecated** — Decision was accepted but is no longer relevant
- **Superseded** — Decision was replaced by a newer ADR (see "Superseded by ADR-NNN")

## File Naming Convention

`[NNN]-[kebab-case-title].md`

Examples:
- `001-application-architecture-pattern.md`
- `002-authentication-strategy.md`
- `003-frontend-architecture.md`

## How to Add an ADR

Run `/design-adrs` to generate ADRs from the workstream decisions, or create a new file manually following the format in any existing ADR.
